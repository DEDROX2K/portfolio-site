Try it

Drag across any words, then pick Highlight. Click a highlight to change its ink.

Reading on a screen is passive. You scroll, you nod, you forget. A highlighter changes that: the moment you drag it across a line, you've decided that sentence matters. This one borrows the selection handles from iOS, then hands you a marker. Every stroke grows from its own random seed, so the tips slant a little differently, the edges wobble, and the ink gets denser where the felt went over twice. Highlights stay on the page when you come back.

On a phone or tablet? This one is built for a mouse or trackpad, so your device's own selection takes over here.

How it's made

  1. The selection stays the browser's

    Nothing replaces native selection, so double-click, triple-click, shift-click and the keyboard all still work. ::selection gets the iOS blue, and everything else is drawn on top. It only switches on for a mouse or trackpad, (hover: hover) and (pointer: fine), because phones already have the real thing.

  2. Handles that line up with the tint

    Each handle is a 2px bar with a round knob, placed on the first and last characters that are actually painted. Every character is measured with Range.getClientRects(), and spaces count too, so a selection ending on a space doesn't leave the handle one letter short. Dragging a knob finds the caret under the pointer with caretPositionFromPoint and moves that end of the selection. The handles glide between letters over 150ms.

  3. A liquid-glass menu

    The capsule is a translucent fill behind backdrop-filter: blur(22px) saturate(190%), with a bright inner top edge and a hairline rim. It springs open from the selection using a CSS linear() spring with about 4% overshoot, glides when the selection moves, and resizes smoothly when "Copy" turns into "Copied". One soft blob slides between the buttons on hover.

  4. Highlights are saved as quotes

    A highlight is a range of characters over the page's text. It's saved as the text plus 32 characters either side, so it can be found again on reload even when other text on the page changes (the clock in the header, say). Overlapping highlights merge into one.

  5. A stroke that's never the same twice

    Each highlight gets a random seed that drives a small generator (mulberry32). It draws three SVG layers: a left chisel tip, a right tip, and a body stretched to fit. The body has wobbly edges, a denser second pass and a few streaks where the felt skipped. box-decoration-break: clone gives every wrapped line its own stroke with its own tips. On dark themes the ink goes solid and the text turns dark, like a marker on paper.

  6. The bug worth knowing about

    The overlay lives at the end of <body>. While you drag-select, the end handle sits right under the cursor, and if the browser hit-tests it, the selection jumps to the end of the page and back, over and over. The fix is one rule: while a selection is being dragged, the overlay gets pointer-events: none.

Build an iOS-style text selection and highlighter for my website in plain JavaScript and CSS, with no dependencies.

Scope
- Desktop only: switch it on when matchMedia("(hover: hover) and (pointer: fine)") matches. Touch devices keep their native selection UI.
- Keep the browser's native selection (double-click, triple-click, shift-click and the keyboard must all still work). Only draw on top of it.

Selection
- Tint ::selection with iOS blue: rgba(0, 122, 255, .24) on light themes, rgba(10, 132, 255, .42) on dark.
- Draw two handles over the selection: a 2px bar the height of the line with a 10px round knob. The knob sits on top at the start and at the bottom at the end.
- Place the handles on the first and last characters that are actually painted in the range. Measure each character with Range.getClientRects, count spaces, and skip collapsed whitespace that has no width. The handles must line up exactly with the blue tint, including when the selection starts or ends on a space.
- Make the knobs draggable. On pointerdown, take over and move that end of the selection with caretPositionFromPoint (fall back to caretRangeFromPoint) and Selection.setBaseAndExtent. Never let the two ends cross.
- Handles glide between characters with a 150ms ease-out, but jump instantly when they first appear and while the page scrolls.
- IMPORTANT: the overlay is appended at the end of <body>. While the user is drag-selecting or dragging a handle, give all overlay UI pointer-events: none. Otherwise the browser hit-tests the handle under the cursor and the selection flickers to the end of the page.

Menu
- When the pointer is released, show a floating capsule centred above the selection (below it if there's no room), kept 8px inside the viewport: "Copy | Highlight".
- Liquid-glass look: a translucent background with backdrop-filter: blur(22px) saturate(190%), a bright inner top edge, a hairline rim and a soft layered shadow, plus a darker variant for dark themes. One translucent blob slides between the buttons on hover. Buttons scale to .92 when pressed.
- Motion: open from the selection point, scaling from .82 to 1 with a spring (a CSS linear() easing with about 4% overshoot, around 560ms). Glide to new positions with the same spring, and animate the width when a label changes (Copy → Copied). Use the separate translate and scale properties so position and scale animate independently.
- Call preventDefault on pointerdown inside the menu so clicking it doesn't clear the selection.
- Copy uses navigator.clipboard.writeText with a document.execCommand("copy") fallback, shows "Copied" for about 700ms, then closes. Esc clears the selection.

Highlights
- Highlight wraps the selected text in <mark class="hl" data-c="colour" data-v="seed">, one mark per text node, splitting text nodes at the edges. Skip whitespace-only text nodes that don't render (no client rect with width), or the mark's padding paints stray blobs.
- Model highlights as character ranges over the page's text. Walk the text nodes and leave out script, style, svg, form fields and any live-updating text. Adding a highlight merges any it overlaps into one.
- Save highlights per page in localStorage as text quotes: { prefix: 32 chars before, text, suffix: 32 chars after, colour, seed }. On load, find prefix + text + suffix in the page's text (fall back to the text alone) and wrap it again. This survives other text on the page changing.
- Clicking a highlight selects all of it and the menu becomes "Copy | 4 colour dots | Remove".
  - A dot recolours the whole highlight in place: keep the selection, keep the menu open, and remember the colour for the next new highlight.
  - Remove erases the whole highlight.
  - While this menu is open, hide the blue tint over marks so the ink colour reads true.

The marker stroke
- Paint each mark with three SVG data-URI background layers: a left chisel tip and a right tip, each 7px wide, and a body stretched between them (preserveAspectRatio="none").
- Use box-decoration-break: clone so every wrapped line gets its own stroke with its own tips. Add padding .06em 7px with a matching negative margin so the ink overhangs the letters without moving any text.
- Generate each stroke from a seeded PRNG (mulberry32), so no two highlights look alike but each one is stable across reloads. Each stroke has:
  - wobbly top and bottom edges (about ±1 unit in a 24-unit-tall viewBox)
  - slanted, slightly rounded tips
  - a denser second pass over part of the stroke
  - 2–3 thin, lighter streaks where the felt skipped
  - a faint darker line along the edges
- Inks on light themes, at about 78% opacity: yellow #ffe94a, green #86f76a, pink #ff8cc6, blue #7dd3ff.
- Inks on dark themes, at about 90%: #ffd60a, #4cd964, #ff5fa8, #40a9ff. Turn the highlighted text dark (#1b1b1c), and drop the edge line, which reads as an outline on dark backgrounds.
- Where one highlight continues across inline elements on the same line, drop the tips at the joins so it reads as one stroke.
- New highlights draw in from left to right (animate background-size). Removed ones erase from right to left.
- Repaint the strokes when the site's theme changes.

Respect prefers-reduced-motion throughout.
